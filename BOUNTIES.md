# MyZubster-Robot Bounties

This repository follows the canonical MyZubster bounty contract:

https://github.com/MyZubster-Ecosystem/myzubster/blob/main/BOUNTIES.md

Repository issues may define robotics, research, market-readiness, documentation or integration work as bounties, but:

- an issue is not proof of completed work;
- an assignment or claim is not proof of funding;
- a PR or merge is not proof of external payment;
- MYZ is currently an internal reward/accounting unit;
- XMR or other external-asset rewards require a separately verified funding and settlement path;
- no silent XMR↔MYZ conversion is allowed.

## Default lifecycle

`OPEN/PROPOSED -> CLAIMED -> SUBMITTED -> UNDER_REVIEW -> VERIFIED/REJECTED -> MYZ_RECORDED -> external settlement only when separately funded and verified`

## Singapore / market-expansion bounties

For readiness and research tasks, the preferred default reward unit is MYZ unless an external treasury reservation is explicitly linked. This avoids presenting an unfunded external-asset amount as guaranteed payment.

Until MyZubster App / Marketplace revenue rails are live and auditable, MYZ does not represent interest, yield, fiat value or an on-chain token. Future fees/revenues and any treasury/founder/maintainer allocation require a separate published governance/accounting policy.
