# Safe-harbor note (Section 2)

## What this kit does NOT do

This kit contains no cryptocurrency generation, wallet signing, mainnet
broadcast, contract deployment, transfer, token authorization, hardware wallet
interaction, multisig, or cross-chain logic. It never connects to any network,
chain, explorer, or payment service.

## The walletAddress field

The genealogy record schema includes a walletAddress field, carried forward from
the #79 Robot DNA kit. In this kit it is:

- Informational only -- the Dashboard and its components never read it, never
  display it, never generate it, never sign it, and never broadcast it.
- Present in the fixture only so the record shape matches what a real fleet
  telemetry feed (or the #79 DNA kit) would deliver.
- A nullable display string, not a live wallet handle.

Defining a nullable wallet-address field in a data schema is pure type work,
explicitly allowed by the safe-harbor type-correction carve-out (the same pattern
accepted in the #79 wallet-field-note.md). It is not monetary work.

## The fee field

The fee field in the record is a dashboard-side statistic (total fee generated by
the robot from completed jobs). It is aggregated by api.getMetrics and displayed
in the Metrics panel as a number with 6 decimal places. No wallet lookup, balance
check, or transaction is performed against this value.
